# 0.7.5rc1 実利用テスト後の修正

この文書はソースの修正記録です。修正後の起動・モデル接続・wheel配布テストの合格記録ではありません。以前作成した0.7.5rc1のwheelは、この修正を含みません。

## 今回変更した境界

- 具体的な依頼文の中に「これは」が含まれるだけで、目的の再入力を求めない。
- 人間の依頼と、プロジェクト憲法・Ownerの引用情報を別フィールドで送る。引用やメタデータを新しい命令・承認へ昇格させない。
- 新しいモデル応答では`response`が回答、`notes`が作業上の留保。空の回答や「変更しませんでした」という報告を、要求された分類の代わりに保存しない。
- 分類の本文は`summary / requirements / learning_items / human_decisions / unknowns / verification_plan`を持つ。検査計画は`NOT_RUN`のまま保存する。
- 引用は、モデルが読んだ版と同じハッシュのファイルまたは記録済み依頼に一致する必要がある。ファイルが変わった場合は停止し、自動的に新しい版へ読み替えない。
- 読み取り専用の回答候補に限り、代替解釈の文章だけが違う場合は不一致を残したまま受領できる。必須・禁止・未解決・関係・具体例の不一致は例外に含めない。ファイル変更の許可条件は緩めない。
- 分類の引用に結び付いた`OWN / REVIEW`候補から少数の学習カードを作る。`REFERENCE / DELEGATE`も分類本文には残るが、学習課題として押し付けない。
- 人間側の理解目標とシステム側の保存方針は独立した提案。規則の自動承認、人間の理解済み認定は行わない。
- 旧台帳の作業メモ・照合結果は上書きしない。新しい表示では、本文のない旧メモを回答として表示しない。

## Crossの配布

Cross VMは任意のネイティブ実行系です。Python wheelだけでVMが同梱されるとは限りません。

探索順は明示した`VERANTYX_CROSS`、パッケージの`bin/cross`、開発ツリーの`cross/build/cross`、PATH上の`verantyx-cross`または`cross`です。見つかっただけでは実行せず、既存のビルドハッシュ照合を維持します。別バージョンのバイナリに合わせてピンを自動更新することはありません。

VMがない場合は`HOST_FALLBACK / CROSS_UNAVAILABLE`として有限比較を行います。VM故障・ハッシュ変更・結果不一致は別の理由として残ります。これらを「意味が正しい」「Cross実行済み」と表示しません。

## 未確認・未完成の範囲

- 今回のAjax課題で、要求を漏れなく意味的に分類できるかは再試験が必要。
- JSONの形、引用一致、検査計画の対応が正しくても、分類内容の意味的正しさは証明されない。
- 元の`UI-basic.mov`やスターターコードがなければ、その内容を確認したとは言えない。
- 意味を汎用的な実行可能検査へ自動変換する能力、学習カードによる実際の理解の獲得は、この変更では保証しない。
- 全プラットフォーム用Crossバイナリの同梱、新wheelの作成、インストール済みCLIの更新、GitHubへの公開は別工程。
