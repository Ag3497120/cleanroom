# 0.7.5rc1 更新候補

## 公開状態

この版はローカルの修正候補です。GitHub への push、タグ、GitHub Release、PyPI 配信、配布用 wheel の作成を、この修正作業では行っていません。既存インストールへ自動配信される更新ではありません。

Vera の目的は、AI が実装の大部分を担っても、人間が目的・判断・理解・経験を保持し、プロジェクトを一緒に育て続けられる共同開発基盤を作ることです。ガードレールや記録は、そのための手段です。

## 修正内容

- 起動時に Application の生成前に端末サイズを取得して落ちる問題を修正したコードを含みます。この起動修正は、今回の回答経路修正より前の実演で確認しました。
- 空のプロジェクト憲章を新しい未解決要件としてモデルに渡さないようにしました。目的や制約が設定されている場合の注入・照合は維持しています。
- 説明・要約など変更ファイルを必要としない依頼では、編集役が実際の回答本文を返すよう指示を追加しました。
- 有限条件の受け渡しゲートを通過し、ファイルが空で回答本文がある場合は、ローカル成果物の `answer.md` と出典付き受領票を保存する経路を追加しました。状態は `RESPONSE_SAVED`、内容の証拠は `UNVERIFIED` です。
- 回答候補を Agent / Notebook に表示し、Owner 側から参照候補として選べるようにしました。変更候補や採用済みファイルとは混同しません。
- 保留時に操作状態を単なる idle に戻さず、確認が必要な状態を表示します。Owner では現在の受け渡し結果と、最後に記録された BUILD / EVIDENCE / OWNERSHIP 評価を分けます。
- Owner の構造化カードは、JSON 全体ではなく説明・理由・理解目標などの本文を優先表示します。参照データ自体は維持します。

受け渡しの不一致、同点、証拠不足を無条件に成功へ変更する修正ではありません。モデル間の一致は意味の正しさや独立検証の証明ではありません。

2026-09-15、機密情報を含まない一時プロジェクトの実 CLI を PTY で起動し、読み取り専用のローカル画面へ表示しました。製品の Web UI を作成したものではありません。

| 操作 | 実演の結果 |
|---|---|
| 起動・終了 | 起動エラーの修正後に確認 |
| Agent から Owner メモへ移動 | 確認 |
| メモ保存・Owner 検索 | 確認 |
| 先頭文字から候補選択・Tab で参照挿入 | 確認 |
| 選択した参照とファイルの送信確認 | 確認 |
| ChatGPT Codex の解釈役・編集役の応答取得 | 確認。独立検証ではない |
| README の3行要約を受け取る | 未達。空の憲章を未解決要件として扱い、受け渡しが保留 |

今回の修正後の再実行、回帰テスト、複数 OS・端末・プロバイダーでの検査、長時間運用、配布物からの新規導入は未実施です。過去の実演結果を、修正後の合格として流用しません。

## 現在の限界と公開前の課題

| 領域 | 現状・残る課題 |
|---|---|
| 短い依頼への応答 | 回答専用の保存・表示を追加しましたが、同じ要約依頼が最後まで成功するかは再実行待ちです。本文の意味的な正しさや依頼の達成を保証しません。 |
| 意図の理解 | 事前ゲートには語句による判定があります。否定文や文脈による誤判定を排除できていません。参照文・憲章・人間の指示を完全に型分離した意味検査でもありません。 |
| コンテキスト回収 | 通常 UI の自動選択は最大8件の小さなテキストファイルです。リポジトリ全体を理解した状態ではなく、大規模な依存関係や広い変更を自動で網羅しません。 |
| 自律実装 | 通常 UI は候補生成・保存が中心です。隔離実行、有限検査、採用計画の低水準機能はありますが、任意の大規模タスクを自律修正して本体採用まで完遂する製品体験は保証していません。 |
| 検証 | 既存の有限条件・出典付き検査と、意味の正しさ・一般性能は別です。別役割のモデルが一致しても独立したオラクルとは呼べません。 |
| 人間の理解 | 学習候補、目標、自己説明の記録はありますが、本人が理解・転用できたことを自動認定しません。学習候補には語句ベースの抽出があり、毎回有用な教材になる精度は未確認です。 |
| 所有の地図 | 判断・仮定・証拠・学習の記録表示はありますが、コード変更ごとに設計理由と技術構成を漏れなく追跡する全体理解地図は未完成です。 |
| モデル接続 | Codex 以外にも API / ローカルモデルの設定経路があります。ただし全組み合わせの認証、構造化応答、再接続、タイムアウト処理は今回実演していません。 |
| 隔離・情報保護 | 候補保存や明示承認は OS レベルの sandbox ではありません。ファイル名による除外だけで秘密情報の不在を保証しません。表示エクスポートにはノート・選択文脈・回答が含まれ得ます。 |
| CLI の使い勝手 | 2入力欄、検索、補完は限定実演済みです。実端末の幅変更、IME、長い出力、Windows などの網羅検査は未実施です。POSIX 固有の処理もあります。 |
| 配信・運用 | 修正後の受入確認、配布物からのクリーンインストール、既存台帳の継続利用、リリース方法とライセンス表記の確認が残っています。自動更新、長期運用・復旧の保証もありません。 |

## 次に必要な受入確認

1. 新しい一時プロジェクトで、初回起動から README の3行要約を受け取るまでを一周させる。
2. `files={}` の回答、変更候補、実際の解釈不一致、空の応答をそれぞれ分けて確認する。
3. 目的・制約のある憲章は引き続き渡り、明示承認なしに本体採用されないことを確認する。
4. 保存した回答・メモが再起動後に表示され、未選択メモが外部送信されないことを確認する。
5. パッケージの構築・新規導入と既存データの継続利用を確認してから、配信先へ明示的に公開する。

このリストは今後の受入条件です。この版で実施済みのテスト結果ではありません。
