# CodexサブスクによるCleanroom中核の実作業検査

実施日: 2026-09-15

## 今回の目的

Veraの目的は、AIが実装の大部分を担っても、人間がプロジェクトの目的、
判断理由、理解、失敗、検証能力を手元に残しながら開発を続けられることです。
ゲーム自体を製品にするためではなく、その共同開発経路を実作業で検査しました。

分類用の技術名辞書や、課題別の実行分岐は追加していません。
生成と意味整理には、実際のCodex CLIのChatGPTログインを使用しました。
WorkとReflectionの呼び出しは逐次実行です。並列エージェントは使用していません。

## 検査の範囲

- 小規模な1画面ゲームを4題用意しました。
- ARKit入力とThree.js自転車を開発用、記憶ゲームと灌漑ゲームを未使用課題として先に定義しました。
- 入力、状態遷移、成功または失敗、再開、説明書、隔離候補の保存を共通の比較軸にしました。
- OS、ライブラリ、入力機器が異なるため、難易度が厳密に同一であるとは主張しません。
- 未使用課題の結果を見てから、Veraのカーネルにそのテーマ専用の例外を足していません。
- ブラウザの操作検査は、今回生成された成果物を対象にした有限の受入検査です。任意の別実装に無修正で適用できる検査器ではありません。

モデル設定は `chatgpt_codex / default` です。
実際にサービス側が選択したモデルの固有名を確定した記録ではありません。
APIキーを転用せず、公式CLIの既存ログインを使用しています。

## 実作業で見つかり、修正したもの

### 1. Codexの構造化出力が受理されない

文字列の `const` や `enum` に型が明示されていないスキーマを修正しました。
プロバイダーへ渡す形式と、Vera内部の完全な検証契約を分離しています。
送信側の互換化を理由に、ローカルの出典・件数・長さの検査は削除していません。

### 2. 120秒の外側タイムアウトが先に実行を止める

内側のモデル設定と外側の実行期限を一致させました。
明示されたタイムアウトは尊重し、ネイティブの失敗理由をホストへ返します。
途中保存した候補を保持し、失敗したのに「回答を保存した」と表示する経路も修正しました。

### 3. コードを回答に書くだけで候補ファイルが作られない

「ネイティブのシェルやツールは禁止」という指示が、
Cleanroomへ返す `write_candidate` 提案まで禁止する形になっていました。

ネイティブCLIによる直接操作と、ホストへ返す型付きツール提案を区別しました。
作成したコードを人間がコピーするのではなく、ホストが許可した候補保存へ進みます。

### 4. 複数ファイルと継続作業が、実際に開ける成果物にならない

版ごとの候補を保ったまま、整合した作業ディレクトリへ展開する仕組みを追加しました。

- 継続元の変更していないファイルも引き継ぐ。
- `read_candidate` で前回の候補版を参照する。
- 変更対象だけ新しい版へ保存する。
- 旧候補を上書きしない。
- 展開時に保存されたサイズとSHA-256を照合する。
- 本体への採用は行わない。

### 5. 外部ライブラリが必要なとき、コード生成だけでは完成しない

自転車課題では、Three.jsが未配置であることをAIが明示して待機しました。
承認済みの依存物を、内容をモデルへ通さずそのまま候補へコピーする
`copy_asset` と、入力時点のサイズ・ハッシュ拘束を追加しました。

今回使用したThree.js r160は、生成候補が要求した版を再現するためのものです。
最新版や本番利用への推奨ではありません。ライセンスも同梱しました。
無制限の依存インストールや、任意のシェル実行を解禁していません。

### 6. 未使用課題の実画面で、横溢れを見つけた

390pxの画面に対し397pxの横幅になりました。
カーネルへゲーム名やCSSの特例を足さず、検査失敗を継続依頼として返しました。
AIが自分で候補を読み直し、レイアウトだけを修正しました。
操作、採点、停止・再開の検査を弱めずに再実行して通過しています。
元の不合格記録も残しています。

## Cleanroomの特徴を確認した結果

### 候補と来歴の確認

4題それぞれについて、次の6項目を確認しました。

- 開ける作業ディレクトリの全ファイルが、記録されたサイズ・ハッシュと一致する。
- 本体へ同名ファイルを採用していない。
- 候補保存を実行検証済みへ昇格していない。
- Workの結果が保存されている。
- Reflectionが確定ではなく提案として保存されている。
- 全Owner項目の出典が、記録に存在する出典集合に含まれる。

24項目すべて通過しています。
件数はこの有限検査の数であり、汎用的な正しさの点数ではありません。

### 意味整理の実例

- ARKit: 開け続けを連続入力にしない設計と、しきい値の個人差。
- 記憶ゲーム: 順番だけを採点し、拍の正確さを採点しないというAIの仮定。
- 灌漑: 残水切れと、畑の水分が尽きることの違い。

固定の技術名から学習カードを選んだ結果ではありません。
選択したReflection AIの、作業記録に結び付いた提案です。
人間が実際に選択した判断や、理解済みの事実とは区別しています。

### 次の作業への引継ぎ

灌漑課題の使い捨てプロジェクトに、明示的な試験用Owner記録を追加しました。
これは実在ユーザーの判断や能力を代行して認定したものではありません。

模擬的に「参照できればよい」を選び、自分用の自己説明と、
共有する引継ぎメモを別々に保存しました。
その後、実際のCodexへREADMEだけの継続作業を依頼しました。

15項目すべて通過しました。重要な観測は次です。

- 次のモデルへ渡した実際のリクエストに、共有メモは含まれる。
- 同じリクエストに、自分用メモは含まれない。
- AIが共有メモの引継ぎ情報を使ってREADMEを更新した。
- 以前のOwnerの選択と、自分用メモが残っている。
- 自己説明は「記録した自己申告」であり、理解済みにはならない。
- 委譲や参照の選択は、実行権限に変換されない。
- ゲーム本体の候補ハッシュは変わらない。
- WorkとReflectionの結果が別に保存される。

この試験は、実際の人間が学習・転用できるようになったことを証明しません。
`human_mastery` は `NOT_ASSESSED` のままです。

## 再実行するための入口

通常のユニットテストから、課金・サブスク消費を伴う実AI呼び出しは行いません。
実AIの試験は、明示したときだけ動くスクリプトです。

リポジトリで仮想環境を有効にし、Codex CLIでChatGPTログインを済ませてから実行します。
`TRIAL_ROOT` はソースリポジトリの外にある使い捨てディレクトリを指定してください。

```sh
export PYTHONPATH="$PWD/core/src"
export TRIAL_ROOT="/absolute/path/to/disposable-cleanroom-trials"

python scripts/core_work_trial.py mouth --root "$TRIAL_ROOT/mouth"
python scripts/core_work_trial.py bicycle --root "$TRIAL_ROOT/bicycle"
python scripts/core_work_trial.py signal --root "$TRIAL_ROOT/signal"
python scripts/core_work_trial.py irrigation --root "$TRIAL_ROOT/irrigation"
```

続きは、表示された実際の作業IDと検査結果を渡します。

```sh
python scripts/core_work_trial.py signal \
  --root "$TRIAL_ROOT/signal" \
  --continue-from "実際のwork-ID" \
  --feedback "独立した操作検査で観測した失敗内容"
```

既に取得して使用を認めたローカル資産は、`--asset` で指定できます。
これは任意URLのダウンロード許可や、依存インストールの許可ではありません。

各呼び出しは成果物を新しい候補へ保存します。
別の生成結果に対して、今回の画面セレクターや操作スクリプトがそのまま合う保証はありません。
受入条件は維持し、実際の成果物に合わせて操作対象を指定する必要があります。

## まだ完成として扱えないこと

### 公開前に中核側で残るもの

- ビルドやブラウザ操作検査を、通常のWorkツールとして実行して正式な検証receiptへ結び付ける経路。
- 検査失敗から修正・再検査までを、日常CLI内で一貫して進める経路。
- 承認済み依存物の指定を、日常UIの迷わない操作へ統合すること。
- 候補確認から、本体への採用までの通常経路との統合。

今回の実行検査は、試験担当がXcodeやChromeで実施し、結果を別の検査記録へ保存しました。
修正指示はCleanroomへ戻していますが、
「Cleanroomが単独でビルド・検査・修正をすべて自律完結した」とは言えません。

そのため、保存時点のWorkが `NOT_VERIFIED` のままであることは意図した境界です。
外側の検査結果を、AIの文章だけで内側の検証済み状態へ書き換えていません。
この接続は重要な中核の残課題です。

### 環境別・拡張側の検査

- 実機ARKit、署名、カメラ許可、個人ごとの口開閉と追跡復帰。
- 別のMac、Safari、Firefox、実機タッチ、音声、アクセシビリティ。
- Claude、API、ローカルモデルの同じ実作業マトリクス。
- 長い会話、大規模リポジトリ、長時間・同時実行、途中終了と再起動の広い組合せ。
- OSレベルの隔離。パス制限と候補保存を、完全なプロセスsandboxとは呼ばないこと。

## 判定

4題の有限な試作と、実AIによるOwner引継ぎは、上記の範囲で確認できました。
カーネルに課題固有の意味判定を追加せず、異なるテーマへ進めたことは確認できています。

これは過剰適合がないことの証明でも、任意のゲームを作れることの保証でもありません。
MVP公開準備100%、実機ARKit合格、人間の学習達成とは判定しません。
成果物の状態、確認できた証拠の範囲、人間に残った記録を分けて扱います。
