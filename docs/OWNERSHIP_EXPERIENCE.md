# 人間に残る共同開発ノート

Veraの目的は、AIが実装の大部分を担っても、人間が目的・判断・理解・
経験を持ちながらプロジェクトを育て続けられることです。
台帳や分類はそのための手段です。

## 日常の流れ

1. いつもどおり仕事を依頼する。
2. 作業結果と実際の作業記録が残る。
3. 作業AIとは独立した整理AIが、判断・原理・参照・委譲・失敗を提案する。
4. 必要なときだけOwnerのReviewから項目を選ぶ。
5. 自分が選んだ関わり方、判断、引継ぎメモが次の仕事の文脈になる。

作業後にノート整理のための必須入力はありません。
Project画面は製品の説明文ではなく、実際の仕事・判断・候補を表示します。

## Ownerでできること

- 原理から理解したい、誤りを見分けたい、参照で十分、委譲したいを選ぶ。
- 後で見る、今回は不要、通常一覧へ戻すを選ぶ。
- 自分の説明、適用例、メモを仕事に結び付けて記録する。
- AIの案を、自分の設計判断として明示的に残す。
- この仕事だけの判断と、プロジェクト全体の方針を区別する。
- 過去の判断を撤回し、その履歴を残す。
- 人間への問いに答え、その仕事の続きを依頼する。
- 同じ仕事を別のAIで整理し直す。

再整理で新しい分類ができても、以前の項目への人間の選択やメモは消しません。
新旧項目が同じ概念かどうかをキーワードで勝手に統合しません。

## 理解と権限の境界

自分で説明を書いたことは、説明を残した事実です。理解済みの認定ではありません。
委譲の選択は人間側の関わり方です。シェル・公開・削除・採用の実行許可ではありません。
人間が方針を保存しても、規則をACTIVEにしたり、候補を本体へ採用したりしません。
AIの判断候補と、人間が明示的に残した判断を別の出典で表示します。

## 自分用メモと引継ぎ

自分用メモ、自己説明、適用例は既定で外部AIへ送りません。
「次の仕事へ引き継ぐメモ」として明示した記録だけを、新しい所有文脈に含めます。
関わり方の選択と共有する設計判断も、送信確認対象の文脈になります。
この文脈には上限と省略件数があり、無制限記憶や完全な回収を保証しません。

## 残る範囲

新しいOwnerカードと旧学習台帳は別の来歴を維持します。
新カードから旧学習課題・独立評価・規則昇格の全機能への自動移行は未実装です。
一般的なシェル実行、ビルド・テスト・修正の自律循環、候補採用の一体化も別途必要です。
この変更ではテスト・実起動・表示確認を実施していません。
