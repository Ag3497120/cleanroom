# 二つの資産を残す CLI MVP

## 製品の中心

外部AIを使うたびに、人間の判断・検証方法・失敗事例を、モデル非依存の実行可能な資産へ変換するシステム。

AIに任せた仕事の中から、自分が後で身につけるべきものと、二度と自分が判断しなくてよいものを分離する辞書。

「二度と判断しない」は無条件の永久許可ではありません。一度選んだ適用条件・例外・検証方法の範囲で再利用し、範囲外や期限切れでは止めます。

## このMacで開く

リポジトリの `mvp.command` を開くと、既存の仮想環境から番号式CLIが起動します。既定では実動作確認に使った合成の作業例が入ったライブラリを開きます。例の分類・自己説明は開発時の操作記録であり、所有者本人の習得記録ではありません。

別の既存プロジェクトには `VERANTYX_LIBRARY` を設定します。

```sh
VERANTYX_LIBRARY=/absolute/path/to/project ./mvp.command
```

新しいプロジェクトは、インストール済みのCLIで一度だけ初期設定します。

```sh
.venv/bin/verantyx --project /absolute/path/to/project setup
.venv/bin/verantyx --project /absolute/path/to/project --lang ja skills --interactive
```

インストールとCross実行器の構築は `QUICKSTART.ja.md` にあります。このMVPのために別の台帳・別のモデル・別のエージェントフレームワークを導入する必要はありません。

## 一つの操作の流れ

1. 外部AIとの仕事の原文を取り込むか、`partner` で新しい依頼を開始します。
2. 回答と一緒に、理由・適用条件・反例・学習候補・再利用候補が既存台帳へ残ります。
3. 学習対象を `OWN / REVIEW / REFERENCE / DELEGATE` から選びます。選ばず後で決めても作業を止めません。
4. 再利用する検証方法を登録します。自然言語の検証案と実行できる検証契約を区別します。
5. 観測対象と保存済み方法を選び、適用範囲と人間の理由を記録します。
6. 次回はその条件で保存済み方法を実行します。再利用のために外部モデルを呼び直しません。
7. 成果レポート、学習辞書、ニュースレターで、今回残ったものを読み返せます。

途中で終了しても、記録済みの原文・判断・失敗を消しません。失敗した生成を成功扱いしたり、自動で呼び直したりしません。

## 番号式メニュー

| 操作 | 目的 |
| --- | --- |
| 1 原文をローカル取込 | 原文と出典を保持する |
| 2 候補を生成 | 取り込んだ仕事を二役で整理する |
| 3 保有対象を選択 | 人間側の所有水準を選ぶ |
| 4 自分の説明を残す | 自己説明を保存する。習得認定ではない |
| 5 便りを作成 | 選択した範囲をローカルMarkdown/HTMLへ出力する |
| 6 一覧を更新 | 同じ台帳の最新状態を読む |
| 7 スキルの中身を読む | 理由・最小限の理解・反例・問い・出典を読む |
| 8 記録済み検証の範囲を登録 | 実行契約と対象を明示的に結び付ける |
| 9 有限検証を確認して再利用 | 表示した契約・対象・主張・観測に限定して実行する |
| 10 成果レポート | PROJECT / SYSTEM / HUMAN をまとめて読む |
| 11 Partnerで相談・実装 | 既存の二役経路へ依頼する。送信前に確認する |
| 12 検証方法をファイルから登録 | 既存形式の仕様を保存し、8・9へ接続する |
| 13 観測を更新 | 対象を読み直し、新しい範囲で9を使う |

新しい依頼は `partner`、仕様ファイルからの検証方法登録は `keep --check`、観測更新は `resume --observe` につながります。

## 学習と自動化は別の軸

`OWN` は原理から理解・設計する対象、`REVIEW` は危険や誤りを判断する対象、`REFERENCE` は引ければよい対象、`DELEGATE` は人間側で覚える対象から外す選択です。

システム側には参照記録・範囲付き方針・実行可能な検証契約・実行結果が別々に残ります。`DELEGATE` を選んでも実行権限は増えません。`OWN` にも自動検証を付けられます。学習候補の表示は最大3件で、明示的に委譲した項目を学習課題として押し戻しません。

メニュー8で、毎回理由を聞く `confirm`、対象確認のみの `assisted`、登録した範囲で追加確認を省く `auto-check` を選べます。`auto-check` でも内容・適用範囲・有効期限・通常の実行権限を検査します。定期的な自動実行ではなく、9で指定した再利用の追加質問を省く設定です。

## 既存基盤への接続

| 入口 | 再利用する既存資源 |
| --- | --- |
| partner | responses.ask、共有文脈、二役連携、省呼び出しモード、作業ループ |
| 原文取込 | external_capture、既存SQLiteイベント台帳 |
| 辞書・説明 | learning、既存の分類・自己説明イベント |
| 検証方法登録 | keep、有限検証仕様、既存の検証計画 |
| 範囲・再利用 | skill_policy、asset_workflow、許可・スコープ・内容固定 |
| 成果表示 | 同じ台帳のスナップショット、成果・失敗・構造体の実行記録 |

並行して状態を持つ新しいデータベースや、自律ループを所有する外部フレームワークは追加していません。

## 外部モデルと使用量

既存のChatGPT認証を使う `gpt-5.3-codex-spark / low` の二役アダプターに接続します。APIキーやパスワードをプロンプトへ貼り付ける必要はありません。

`partner` の会話モードは提案と回答の最大2回。実装モードは既存の省呼び出し経路を使い、検証側の解釈計画と実装側の編集を最大2回で行います。初期提案と最終整理はローカルLLMではなく、既存の決定論的処理です。

資産を読む・分類する・自己説明を残す・保存済み検証を再利用する操作はモデルを呼びません。

```sh
.venv/bin/verantyx --project /absolute/path/to/project partner "依頼を書く" \
  --creator-adapter /absolute/path/to/implementation.json \
  --reviewer-adapter /absolute/path/to/verification.json \
  --mode discuss --key unique-task-key
```

実装候補は `--mode implement --include relative/file.py` で依頼します。候補生成と実ファイルへの適用は別です。適用・実行は既存の作業ループと明示的な許可を通します。同じモデルの二役なので、合意を独立した正しさの証明にはしません。

呼び出し上限は二役で共有し、失敗も消費として残します。回数の上限はトークン量・金額の厳密な上限ではありません。開発用の既存6回枠は実動作確認で消費済みです。勝手に初期化し直しません。新しい利用枠は利用者が用途と上限を決め、`codex-config --directory ... --max-calls ...` で作成します。

## 立体十字の扱い

既存Cross VMの有限ルーティングと解釈・編集の照合を使用します。今回の実モデル応答にも `CROSS_VM / COMPLETE` の実行記録が残っています。辞書の六方向の表示とは区別します。

- 出典・適用範囲・対象の主張・反例・決定権・結果を混ぜません。
- 構造の一致を独立した文書の一致として加算しません。
- 根拠不足や不一致を多数決で確定しません。
- 回答時点の経路は、現在の実行許可ではありません。
- 幾何の優位・無限記憶・モデル蒸留の性能を今回の実績として主張しません。

## 実動作で確認した範囲

2026-09-11、合成の再試行上限の仕事で確認しました。

- 実モデル二役が一度で通り、学習候補3件と再利用候補が保存されました。
- 前の仕事の失敗も、次の候補生成の参照に含まれました。
- 番号メニューから技能・理由・反例・出典を読めました。
- 固定期待値3を変えず、保存済み方法の再利用が `COMPLETED / BOUNDED` になりました。
- 値4に対する反証、対象外の拒否、同一キーの再実行抑止も記録されています。
- 期限切れでは `OBSERVATION_EXPIRED` で止まり、明示的な再観測後に実行できました。
- 学習分類・説明・レポート・有限検証の再利用には外部LLMを呼びませんでした。

これは有限条件と合成素材の確認です。プログラム全体の正しさや利用者本人の習得を保証しません。表示される `BUILD / EVIDENCE / OWNERSHIP` は元の仕事についての判定であり、このツールの起動・回答整理の完了とは別です。

## 残っている範囲

- 任意の自然言語の判断を、安全な実行規則へ全自動で変換する一般機構。今は具体的な有限仕様と明示的範囲が必要です。
- 基盤を通らない外部AI利用の自動収集。明示的な取込と、この基盤の呼び出しが対象です。
- 今回追加した partner 実装モードで、実モデルから大きな実プロジェクトの適用までを通す新しい確認。
- 別ベンダーへの切替を伴う実モデル比較、全OSのインストーラー、公開配布・ホスティング。
- 人間の習得の外部認定。説明の保存と理解を区別します。

公開時に、実ユーザーの `.verantyx`、記憶、認証情報、開発用ライブラリを同梱してはいけません。
