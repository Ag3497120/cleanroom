# Two ideas, one CLI workflow

## Purpose

外部 AI の応答を消費して終わらず、次の二つを作業の中に残します。

1. 人間の判断・検証方法・失敗事例を、出典と適用範囲を持つ再利用可能な資産にする。
2. 自分が後から身につけることと、仕組みに委ねたいことを分ける。

これは新しいエージェント群や別の記憶台帳を増やす機能ではありません。既存のイベント台帳、検証契約、資産カタログ、学習辞書を `keep` から操作します。

## 1. 作業後に、何を残せるかを見る

```sh
verantyx keep RUN_ID
```

記録された判断、保存済みの検証方法、失敗事例、学習候補を区別して表示します。表示はモデルを呼ばず、学習開始・委譲選択・ルール有効化・テスト実行を行いません。

まだ検証方法がない場合、文章が残っているだけで「実行可能な資産ができた」と扱いません。記録がないことも、そのまま残します。

## 2. 自分が学ぶか、仕組みに委ねるかを選ぶ

```sh
verantyx keep RUN_ID --learn LEARNING_ID --reason "今後も設計判断に使うので自分で理解する" --key keep-learn-001
verantyx keep RUN_ID --delegate LEARNING_ID --reason "条件を固定した検証を仕組みに委ねたい" --key keep-delegate-001
```

同じ候補を二重の辞書へコピーするのではなく、既存の学習イベントに `OWN` または `DELEGATE` の選択と理由を記録します。過去の選択は履歴に残り、後から方針を変えられます。

```sh
verantyx dictionary --view learn
verantyx dictionary --view delegate
```

`REVIEW` と `REFERENCE` の細かい選択は既存の `learn-target` で引き続き行えます。未選択の提案を勝手に `DELEGATE` にしません。延期中の項目を閲覧・分類しただけで学習を再開しません。

## 3. 検証方法を、次回も実行できる契約として保存する

```sh
verantyx keep RUN_ID --check checks/retry-policy.json --key keep-check-001
```

`--check` の入力は既存の `verify-plan --spec` と同じ形式です。対象・主張・有限の検査項目を定めた検証仕様を、既存の検証計画へ登録します。書式を一から覚えずに作る場合は既存のテンプレートを利用できます。

```sh
verantyx verify-template RUN_ID --claim CLAIM_ID --target settings.json --output checks/retry-policy.json
```

登録だけでは検証を実行しません。保存された計画の状態と識別子を使って、必要な時に既存の `verify-run` を明示的に呼びます。別の仕事で使う際も、既存の `asset-template` や資産ワークフローで現在の対象・主張・適用条件へ結び直します。

自然言語のアドバイスや「大丈夫」という AI の発言を、正しい検証プログラムへ無条件に変換する機能ではありません。具体的な有限契約がまだなければ、資産化は未完了です。

## 対話 CLI から使う

回答後に、任意の操作として `/keep` を案内します。学習を強制する質問は挟みません。

```text
/keep
/keep learn LEARNING_ID 自分が判断できるように理解したい
/keep delegate LEARNING_ID 同じ条件の確認は仕組みに委ねたい
/keep check "checks/retry-policy.json"
/keep RUN_ID
```

変更操作は直近の作業に対して実行します。通常の CLI と同じ権限経路を通り、独立した承認・採用の抜け道にはなりません。署名された操作では `--check` の入力ファイルも承認対象へ結びます。

## 保持する境界

- 提案、判断、実行許可、実行、検証、採用は別の記録です。
- 検証方法の登録と、その検証の成功は別です。
- 失敗や反例は、成功した記録だけを残すために削除しません。
- 学習の選択は習得済みの証明ではありません。
- 委譲したいという方針は、無条件・永久の実行許可ではありません。
- 判断を省略できるのは、既存の規則や検証資産が現在の条件に適用できる範囲です。
- `keep` はモデル呼び出しを追加しません。既存の立体十字によるルーティング・受け渡し判定は保持します。
- Web は今回の対象外です。
