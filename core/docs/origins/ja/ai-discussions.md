# AIとの議論と、定義の修正

[English](../en/ai-discussions.md) · [資料一覧](../README.md)

これは提供された議論の編集要約です。会話全文や検証済みの技術的主張ではありません。

## 入口の定義を修正した

初期の説明は「作業前に判断を仕分け、作業後に規則・検査・失敗・学習候補を保存するCLI」でした。作者はそれでは目的が狭くなると修正しました。

**Veraは、AIが実装の大部分を担う開発において、プロジェクトの目的、設計判断、検証方法、失敗、技術的理解を人間側へ残し、人間がプロジェクトを理解しながら一緒に育て続けられるようにする共同開発基盤です。**

判断権、証拠、UNKNOWN、規則昇格は、その目的を支える手段です。独自審査の多さを製品価値にはしません。

## 三つの役割を混ぜない

- 選択したAIが、普通に文脈を読み、調査・実装・修正を進める。
- 選択可能な整理AIが、作業中と作業後に意味や学習候補を提案する。
- Vera Kernelが、権限、出典、実行事実、版、本人の選択、資産の状態を保存する。

意味を単語一致で決めません。異なるモデルや同じモデルの別回答を許容し、来歴を残します。整理失敗を制作失敗へ変換しません。AIの文章を、人間の承認・習得・検査成功へ変換しません。

## 作業台付きの研究ノート

Agentは左、Ownerは右。人間が大量の記録を整理するのではなく、仕事からノートが生まれます。目的、判断、AIの仮定、検査の範囲、不明点、本人が持ち帰りたい理解を並べます。

空欄Enterで依頼・メモ・検索を巡回し、必要なOwner記録だけを補完で依頼へ差し込みます。学習の量と重さは本人が決め、スキップを理解不足と診断しません。

## 今も区別するもの

BUILD / EVIDENCE / OWNERSHIPは別状態です。コードが完成しても理解回収は次回で構いません。理解を記録しても検証が済んだとは限りません。詳しい現在の挙動は操作ガイドとソースを参照します。
