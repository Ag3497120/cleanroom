# 開発記: 個人プロフィール、スキル、検証

[English](../en/development-history.md) · [資料一覧](../README.md)

提供された三つの実装記録を整理したものです。過去の修正要求を新たに適用するものではありません。

## 1. 個人の技術スタックと、次回へ続く学習

経験は本人の言葉で登録し、初回を短く、後から新しい主要技術を選んだ時にも追記できる設計へ進みました。「ここまでできる」は自己申告として扱い、AIへGit pushを頼むことや、急いで学習をスキップすることから能力を推定しません。

日記・選んだ技術・本人の説明はプロジェクトを越えて同じユーザーのローカル資産へつながります。提案は本人の量・重さ・タイミングに従い、次の似た仕事へ少しずつ継続します。相談内容から人を診断する機能ではありません。

## 2. 二段階のスキル

AIが使える手順はまず候補として保存します。本人は理解したいもの、参照できれば十分なもの、任せるものを選びます。AIの手順数と本人の習得数は同じではありません。ビンゴに似た盤面は、空白を欠点にしたり、全てを埋める義務にしたりしません。

## 3. 作業途中の情報を残す

完成後の一般的な解説だけでは情報が失われます。実装中の前提、選択肢、失敗条件、ツール記録を出典付きで残し、後から要約と詳細を選べる方向へ進みました。記録の欠落を技術名から推測して埋めません。

## 4. 外部接続と来歴

外部ハーネス、OSSサンドボックス、MCP、Obsidian、他エージェントのスキル移植、モデル交代時の文脈引き継ぎを拡張点として扱いました。外部操作を観測できない場合は「本体未変更」と断定しません。取り込んだスキルを本人の習得にしません。

## 5. 20プロジェクト評価

自然な依頼、文脈参照、Ajax、読み取り専用調査、数値43の契約、権限、移行、API互換性、モデル交換、Reflection障害などを分けて見る課題群が提案されました。作業完了というモデルの発言と、外部の評価結果を分離します。この記録は20件の合格報告ではありません。

## 6. 公開準備

CLIを主役にし、Pagesは体験入口、verantyx.aiは紹介、My Atlasは私的な経験の可視化とします。デモ録画には架空の公開用データだけを使います。実装途中の公開ノートであり、以前の文章に含まれる名称変更やテスト指示は再実行しません。
