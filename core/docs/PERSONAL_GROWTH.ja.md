# My Notebook: プロジェクトと一緒に、自分の経験も育てる

Veraは、AIが実装の大部分を担う開発において、目的、設計判断、検証方法、失敗、技術的理解を人間側へ残す共同開発基盤です。My Notebookは、そのうち「自分に何を残すか」をプロジェクトを越えて継続する本人用のノートです。

この機能は新しいソース実装です。この変更に対する起動確認、実モデルでの対話、回帰テストはまだ実施していません。既存リリースの検証結果を、この機能の検証結果として扱わないでください。

## 守ること

- AIにGit pushを任せた回数、説明を省いたこと、学習を後に回したことから、能力や自信を推定しません。
- 未登録は「経験がまだ記録されていない」であり、未経験ではありません。
- 経験、理解、自信、希望する助け方、目標、委譲を別々の自己申告として保存します。
- AIの学習分類、本人の自己申告、実際の作業記録を混同しません。
- 学習量を選ぶのは本人です。仕事の完了や実行権限は、学習への参加に依存しません。
- 理解度の点数、連続日数、未提出の宿題、期限による催促は作りません。
- 同じ回答、同じ分類、複数モデルの一致は要求しません。意味の整理は別版として残します。
- 「以前失敗して自信がない」という相談は、能力の不足や診断に置き換えません。

## 入口

通常は verantyx で起動し、F2のメニューから選びます。

| メニュー | 役割 |
| --- | --- |
| My profile | 経験、理解、助け方、目標、委譲を自分の言葉で記録・修正 |
| My journal | 各プロジェクトで作ったもの、AIの見方、自分の一言 |
| Next time | 理解する・参照する・任せる・次回に続けるの選択 |
| My pace | 提案の量、重さ、タイミング、共有、今日だけ静かに |
| Talk | 相談、自然な言葉によるプロフィール・希望の更新案 |
| Portfolio | 日記と自分の説明から、公開候補だけを選ぶ |

Owner欄には個人ノートの件数と今回の小さな一歩を表示します。個人記録もOwner検索とAgent入力の参照候補から選べます。選択した項目だけを依頼に添付する既存の操作を使います。個人データは読み取り専用watchの公開スナップショットには追加しません。

設定へ直接進む場合:

~~~sh
verantyx setup profile
verantyx setup pace
verantyx my-profile
verantyx my-journal
verantyx my-portfolio
~~~

スクロールバックUIではNotebookのメニュー、または /profile、/journal、/next、/pace から開けます。これらのコマンドを覚えなくても操作できます。

## 初回は小さく

初回の質問は本人単位で一度だけです。プロジェクトを変えるたびに最初から聞きません。

「AIと小さなPythonアプリを作った」「Swiftは読めるが設計は相談したい」のような自由記述で構いません。最初は思いつく技術を一つだけ書くか、スキップできます。

Light、Private、Together、Skipから始め方を選べます。共有を選ぶ場合も、どの内容がAIに渡るかを先に説明します。本人の記入を合否判定や利用機能の制限に使いません。

新しい主技術を本人が選んだ場合、作業AIは短い経験確認を提案できます。Veraは表示回数を制限します。すべての依存ライブラリで質問する設計ではありません。答えず進めても、能力を下げたり仕事を失敗扱いしたりしません。

技術が新しいか、今回の主技術か、何を学ぶ価値があるかは選択したAIの解釈です。キーワード分類で決めません。したがって質問や提案の質はモデル依存で、完全な意味理解は保証しません。

## 学習の重さと継続

設定はプロジェクト共通です。

| 項目 | 値 |
| --- | --- |
| 提案方式 | on_demand / light / guided |
| 重さ | brief / snippet / practice |
| タイミング | after_work / at_breaks / on_demand |
| 上限 | 1作業0〜3件、1日0〜12件 |
| 期間 | この起動中 / 今日だけ / 今後のプロジェクト共通 |
| 主技術の経験確認 | 任意の質問を許可 / 自分から登録 |
| AI共有 | 本人が選んだ抜粋を共有 / 共有しない |

既定の短い始め方は、1作業1件・全プロジェクト合計で1日1件までです。at_breaksは現在、WorkResultが保存される作業単位の区切りを指します。編集中の任意の瞬間に割り込む機能ではありません。

Next timeは、次の関連する仕事へ持ち越す文脈付きのしおりです。期限はありません。本人が共有した過去の学習候補と選択をAIへ渡し、続きを提案する場合は前の項目IDと今回の追加点を残します。

REFERENCE・DELEGATE・DISMISSを選んだ項目を、コード側で強制的に学習へ戻しません。同じ技術の別名や新しい提案まで完全に重複排除できる保証はありません。本人の選択を尊重するようAIへ渡す方針と、引用された既存項目に対する機械的な制約を併用します。

Pythonで学んだ考え方をSwiftにつなげることはできますが、Pythonの経験だけでSwiftも習得済みにはしません。

## 自然な相談と更新

Talkでは、例えば次のように話せます。

~~~text
以前GitHubで失敗して自信がない。今回は差分を一緒に見てほしい。
今日は説明を少なくして、実装を進めたい。
Swiftのコードを前より読めるようになった。
~~~

送信前に確認し、選択した整理AIが回答と更新案を作ります。更新案には元の発言の引用と出典を必要とします。本人が採用するまでプロフィールには反映しません。

その場だけ、今日だけ、今後も共通で使う、を本人が選びます。「今日は」を勝手に永久方針へしません。通常のAgentとの会話でも、AIは明示的な自己申告についてプロフィール更新の下書きを作れます。依頼の仕方から勝手に推測する機能ではありません。

相談終了時には、下書きを自分用に残すか削除するか選べます。採用済みの自己申告は別の記録です。相談を自然に開ける場所は用意しますが、個人的な失敗や不安を無理に聞き出しません。

## 日記と実績

一つの仕事から、まず以下の事実を個人日記へ保存します。

- プロジェクトと依頼
- WorkResultの状態と出典
- 候補ファイル、対象ハッシュ、ツール結果の件数
- 記録済みの検査イベント
- 実際の人間回答・設計判断イベント

有効な整理AIと共有許可がある場合に、技術についての観測候補、人間とAIの貢献についての解釈、仮定、失敗、UNKNOWN、小さな学習候補を別版で追加します。日記に本人の一言も残せます。

「説明を書いた」「試して気づいた」「別の場面で使った」は本人の記録として積み重ねます。それだけで合格・習熟済みとは認定しません。

Portfolioは、本人が選んだ日記と自己申告・自分の説明だけを書き出します。AIとの共同制作であることを表示し、AIが書いたコードを本人の独立した実装経験と偽りません。将来の目標は目標として表示します。非公開の相談、全依頼文、パス、ハッシュ、AIによる能力推定は既定の出力に含めません。プレビュー後にローカルJSONへ保存し、自動投稿はしません。

## 保存と共有

macOSの既定の場所:

~~~text
~/Library/Application Support/Verantyx/Personal/profile.sqlite3
~~~

その他の環境は XDG_DATA_HOME/verantyx/personal、未指定なら ~/.local/share/verantyx/personal です。VERANTYX_PERSONAL_HOME に絶対パスを指定して分離できます。同じOSユーザー・同じ保存場所ではプロジェクト共通です。クラウド同期や複数人の共有アカウントは実装していません。

本人用ディレクトリとデータベースには限定したファイル権限を使います。暗号化ストレージ、他のローカルプロセスからの強固な隔離、遠隔ワイプを提供するものではありません。

AIには、共有を選んだ自己申告、学習候補と本人の選択、明示共有のメモだけを、件数・サイズ上限付きで渡します。全プロジェクトの生の会話やコードを自動共有しません。全体の共有スイッチがオフなら、個別に共有とした記録も自動送信しません。

Owner参照候補から明示選択した項目は、今回の依頼に含める別の送信意思として扱います。選択送信の前には既存の文脈確認を行います。

共有した情報がAIの回答、プロジェクトの作業記録、接続アダプターやプロバイダーの履歴へ引用される可能性は残ります。個人ノートからの削除は、それらの履歴の削除や物理的な安全消去ではありません。

## 任意のコマンド

~~~sh
# 自分の経験を登録。既定は非共有
verantyx my-profile set --technology Swift --kind experience --text "読めるが設計は相談したい"

# 今日だけ、自分から開くまで静かにする
verantyx my-profile pace --mode on_demand --scope TODAY

# 共有を選び、短い提案を1日1つまで
verantyx my-profile enable
verantyx my-profile pace --mode light --weight brief --daily-limit 1 --per-work 1 --share-context yes

# 本人用データを見る。これだけでAIは呼ばない
verantyx my-profile show --json
verantyx my-journal show --json

# 非公開の書き出し。公開しないこと
verantyx my-profile export --include-private --output /absolute/path/personal-private.json

# 別Macで自己申告を取り込む。共有はオフ、設定は維持
verantyx my-profile import --input /absolute/path/personal-private.json --yes
~~~

現時点のimportは自己申告のみを扱います。日記・解釈・実行証拠を検証済み状態として移植するものではありません。exportにはそれらの記録も含み、機械可読な参照用として持ち出せます。5,000件または8MBを超えるexportは、欠けたバックアップを成功扱いせずエラーにします。分割・完全移行は今後の範囲です。

## 実装上の分離

~~~text
Work Agent
    -> 実際の作業・候補・結果を保存
    -> 個人日記へ事実を記録
    -> 選択したReflection AIで任意の個人整理
    -> AIによる学び・プロフィール更新の候補
    -> 本人の選択で採用・参照・委譲・次回
    -> 共有を選んだ抜粋だけ次の仕事へ
~~~

作業結果と個人整理の失敗は分離しています。個人モデル呼び出しは別の生成ID・モデル情報・出典範囲を持ちます。失敗・結果不明の呼び出しを、画面の再描画で自動再試行しません。別モデルで整理するにはModelsで整理AIを選び、元のプロジェクトでMy journalから新しい解釈を追加します。

規則の有効化、ファイルの採用、コマンド実行権限は既存のVera Kernelが扱います。個人の「委譲したい」という希望だけで、それらを有効にしません。

## 現在の限界

- 人間の理解を客観的に測定したり、長期的な学習効果を証明したりする機能ではありません。
- 主要技術の抽出、学習内容、会話からの更新案の質は、選択したAIに依存します。
- 個人整理は追加のAI呼び出しです。料金・時間が増える場合があります。Private、on_demand、Reflection offで抑制できます。
- 表示と共有には件数・サイズ上限があります。古い全記録を毎回の文脈へ入れる無限記憶ではありません。
- 過去のすべての仕事を遡って自動移行しません。元のプロジェクトで明示的に整理した仕事から日記へ回収できます。
- 完全なバックアップ復元、クラウド同期、教育機関向けの本人評価・教員権限は未実装です。
- 今回追加した経路の起動・実モデル・回帰検証は未実施です。


## My Skills: AIの手順と本人の経験を分ける

F2のMy skills、またはverantyx setup skillsから、二段階のスキル盤面を開けます。
AIが作った手順の数を本人の能力に置き換えません。
必要な項目だけ選び、自己申告、自分の説明、適用例、転用例を別の来歴として残します。
My paceの共有設定に加えて項目単位で共有を選んだ記録だけ、次のプロジェクトの個人文脈へ入ります。
本人が残したスキルの説明・実例は、Portfolioで日記と一緒に選べます。
