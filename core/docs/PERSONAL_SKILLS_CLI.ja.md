# 外部AIとの仕事を個人技能へ残すCLI

実装状態: 最初の接続を追加。今回の変更に対するテスト・実モデル呼び出しは未実施です。

## 維持する二つの思想

1. 外部AIとの仕事から、判断・理由・検証方法・失敗例を、特定モデルに閉じない資産として残す。
2. 自分の技能として持つものと、AIに委ねるものを区別し、学習と分業を調整する。

取り込んだ文章、AIが作った候補、人間が選んだ分類、実行契約、実行結果、自分による理解の説明は区別します。
ログに「テスト済み」と書かれていても、それだけでVerantyxによる検証済みにはなりません。
候補は自動採用せず、分類は実行権限や習得証明に変換しません。

## 保存先

既存のVerantyxワークスペースを一つ、個人ライブラリとして使います。
以下ではその設定済みディレクトリを LIB とします。
未設定の場合は既存の setup で初期設定してください。

~~~sh
LIB="/absolute/path/to/personal-library"
verantyx --project "$LIB" setup
~~~

既存のプロジェクト台帳を再利用します。別の技能データベースやモデル専用形式は増やしません。
複数の作業元は --origin-project で区別します。これは出典のラベルであり、
作業元ディレクトリの読み取り権限や書き込み権限ではありません。
複数の独立したライブラリの自動統合は今回の対象外です。

## 取り込み

~~~sh
verantyx --project "$LIB" skills-import \
  --input /absolute/path/to/selected-work.txt \
  --origin-project small-project \
  --label retry-limit-decision \
  --provider chatgpt \
  --model gpt-5.3-codex-spark \
  --mode assisted \
  --key import-small-01
~~~

--provider と --model は取り込み元に関する自己申告です。認証された実行履歴にはなりません。
選んだ原文は全体を保存します。1回の上限はUTF-8で64KiBです。
上限を超えた入力は拒否し、末尾を黙って切り捨てません。
大きいプロジェクトでは、関連する会話・判断のまとまりごとに分けて取り込みます。
モデル重み、USBの記憶全件、別アプリの履歴を自動収集する処理はありません。
秘密情報は取り込む前に取り除いてください。自動資産化では選んだ内容が設定先のモデルへ渡ります。

取り込みのモード:

- manual: 原文と出典だけを保存。モデル呼び出しなし。
- assisted: 原文を保存し、短い原文プレビューを返す。候補生成は明示的な skills-build まで待つ。
- auto: 原文保存後、作成役の提案と検証役の応答を順に取得する。自動採用・実装・実行はしない。

assisted のプレビューは抽出済み技能やAI要約ではありません。
同じ --key と同じ入力の再送は保存済みの結果を返し、別の入力を同じキーへ上書きしません。
意図的に新しい処理を始める場合だけ、新しいキーを使います。

## 二役による候補作成

取り込みが返した run_id を RUN に指定します。
既存のcodex-configで作成した、implementation役とverification役のアダプタを使います。
実モデルとして指定されているのは両役ともChatGPT認証の gpt-5.3-codex-spark、reasoning low です。
このドキュメント作成時にはモデルを呼び出していません。

~~~sh
RUN="skill-RETURNED_ID"
verantyx --project "$LIB" skills-build "$RUN" \
  --creator-adapter /absolute/path/to/implementation.json \
  --reviewer-adapter /absolute/path/to/verification.json \
  --key build-small-01
~~~

auto 取り込みでは同じ二つのアダプタを skills-import に指定します。
作成役の提案1段階、検証役の応答1段階の固定フローです。自動修復ループは追加していません。
既存の共有呼び出し予算とアダプタ設定を使用します。実際のトークン消費量がゼロになる仕組みではありません。
同じモデルを使う二役は、独立した正しさの証明にはなりません。
skills-build も候補を作る経路であり、実行契約の合格や技能の習得を保証しません。

取り込み、一覧、説明の保存、下書き生成だけなら、モデル呼び出しは不要です。

## 一覧・四分類・自分の説明

~~~sh
verantyx --project "$LIB" skills-stack
verantyx --project "$LIB" skills-stack --query routing
verantyx --project "$LIB" skills-stack --target OWN
verantyx --project "$LIB" skills-stack --run "$RUN"
verantyx --project "$LIB" keep "$RUN"
~~~

対話コンソールでは /skills または /skills routing から一覧を開けます。

分類は既存の学習・委任コマンドと同じ四種類です。

- OWN: 自分の技能として理解し、扱えるようにしたいもの。
- REVIEW: AIの結果を確認するために理解を保持したいもの。
- REFERENCE: 必要なときに説明や根拠を参照できればよいもの。
- DELEGATE: 記録した適用条件の中でAIへ委ねたいもの。

モデルからの分類提案と、人間が選んだ分類は別表示です。
具体的な分類変更や候補採用には既存の keep と学習コマンドを使います。
skills-stack の語句検索は技能・再利用候補への文字列フィルタです。
方法・失敗記録の全文検索や、意味検索・学習済みランキングではありません。

記録済みの学習候補に、自分の言葉で説明を残せます。

~~~sh
verantyx --project "$LIB" skills-explain "$RUN" \
  --candidate RECORDED_CANDIDATE_ID \
  --statement "自分がこの判断を必要とする理由と、適用しない条件を説明する。" \
  --key explain-small-01
~~~

これは自己説明の記録です。自動採点、AIによる理解確認、習得認定はまだ行いません。
原文を保存しただけで学習候補がない場合、説明の保存対象はありません。

## 範囲を固定したニュースレター下書き

先に対象を明示して一覧を取得し、その scope ID を使います。
run、limit、状態の版が同じことを確認してから下書きを作る設計です。

~~~sh
verantyx --project "$LIB" skills-stack --run "$RUN" --limit 12
verantyx --project "$LIB" skills-newsletter \
  --run "$RUN" --limit 12 \
  --scope-id RETURNED_SCOPE_ID \
  --title "今週、自分の技能として残したこと" \
  --format markdown \
  --output skill-newsletter.md
~~~

--run を繰り返すと複数の履歴を選べます。--format html も使えます。
--output を省くと下書きを標準出力に返します。
既存ファイルの上書き、公開、メール送信、外部サイトへのアップロードは行いません。
ファイル出力は既存の出力先制約と権限確認を通ります。
選択後に台帳が変わると範囲IDが変わるため、一覧を取り直してから生成します。
検索語句・分類で絞った一覧の範囲IDではなく、上の対象runだけを選ぶ一覧を使ってください。

下書きは全履歴エクスポートとは別です。表示上限は12作業、分類ごとに8記録、
参照一覧ごとに16件、値ごとに1000文字、全体の内容40000文字です。
上限による省略は下書き内に明記します。原文台帳は変更しません。
Markdown中の外部文はリテラル表示、HTMLではエスケープし、
外部リンクの実行、画像の読み込み、スクリプトを追加しません。

## 立体十字構造体との接続

技能ごとに中心IDと六つの面の情報を作り、一覧の graph に返します。

- +x: 元の出典。
- -x: 最小限の理解・説明。
- +y: 今扱う理由。
- -y: 反例・適用しない条件。
- +z: 自分で確認する問いや方法。
- -z: 保有・委任の対象、提案と選択の区分、習得評価の状態。

これは既存台帳からの関係情報の投影です。
新しいVMの実行、暗号化、モデル蒸留、ルーティング学習、速度改善の実証ではありません。
作成・応答生成には既存の propose / compose 経路を使用します。
「構造体がある」ことと「構造体による性能優位がある」ことは別に扱います。

## 次の実装範囲

- 自動確認・補助・毎回確認の再利用ポリシー切り替え。
- 技能ごとのAI実装範囲の変更と、実行側での強制。
- 自分の説明に対する理解確認と、関連技術資料への導線。
- 人間が採用する前の、範囲を限定した隔離試行。
- 大きいモデル研究プロジェクトでの明示的な履歴選択と利用。
- 今回追加したCLIの動作確認と、指定モデルによる二役経路の確認。

Web、配信、常駐監視、テストの大量追加は先行させません。
