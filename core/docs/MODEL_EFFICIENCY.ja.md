# モデル利用効率と入力欄の改善（2026-09-17）

Codex / Claude Code が提供する会話継続と、各APIのプロンプトキャッシュを利用するように変更しました。
不要な再送と自動の追加呼び出しを減らす実装です。本家と同じ料金・利用枠消費・キャッシュ率を達成した、という実測結果ではありません。

## 変更内容

| 接続方法 | 今回の変更 |
|---|---|
| Codex CLI / ChatGPTログイン | 同じWork run内は、成功が確認できたセッションIDを指定して `exec resume`。初回以外は変更したフィールドと追記した履歴だけを送信 |
| Claude Code / Claudeログイン | 同じWork run内は `--session-id` / `--resume` で継続。システム指示のsnapshotを有効にして、固定の実行ディレクトリから差分を送信 |
| OpenAI API | 固定の文脈、完了したツール結果、変動する状態の順にJSONを分割。`prompt_cache_key` を設定し、GPT-5.6以降のモデル名には明示的なキャッシュ境界を設定 |
| Claude API | 固定の文脈と完了したツール結果に `cache_control` を設定。既定の5分キャッシュを使い、毎回変わる末尾には境界を置かない |
| OpenAI互換API | 独自のキャッシュ拡張を送らず、既存の互換形式を維持 |

ネイティブCLIへ渡すWork用出力スキーマは、参照IDが増えるだけでは変化しないようにしました。
IDの有効性はホスト側で引き続き検証します。初回に渡した画像も、継続時には再添付しません。

同じrunでも、履歴の書き換え・圧縮、共有ファイル範囲・添付・権限・モデル・指示・スキーマの変更があれば新しい会話にします。
成功したことが確認できない前回の会話も継続せず、結果不明のリクエストを自動再送しません。
他の作業のセッションを `--last` などで拾うことはありません。

固定の実行ディレクトリはプロジェクト外の空ディレクトリです。Codexのシェル・Web・サブエージェント、
Claude Codeのネイティブツール・MCP・hooksなどに作業を委ねる設定には変更していません。
ファイルやツールの操作は従来どおりCleanroom側で管理します。

## 追加のモデル呼び出しを減らす

新規プロジェクトのReflectionは手動を既定にしました。このMacの対象プロジェクトも手動に設定しました。
作業後の独立した整理モデル呼び出しを毎回自動で追加しません。
作業モデルの応答に含まれる学習メモの取り込みは継続します。

既存の他プロジェクトの設定は維持します。必要ならModels画面でReflectionを選び直せます。
手動の整理操作では、Reflectionがoffでも現在のWorkモデルを使って整理できます。この明示操作ではモデル利用が発生します。

## 利用量の確認

TUI内で `/usage`、ターミナルでは次のコマンドを使います。

```sh
verantyx --project /Users/motonisihikoudai/Downloads/simureal/cleanroom model-usage
```

結果を受信した呼び出しについて、プロバイダーが報告した入力・出力・キャッシュ読み取り・書き込み・用途を記録します。
入力とキャッシュ済み入力の両方が報告された呼び出しだけを使って、キャッシュ再利用率を計算します。
未報告は0とみなしません。Claudeの入力合計には通常入力・キャッシュ読み取り・書き込みを一度ずつ含めます。
推論トークンを出力トークンに重複加算しません。

この集計は更新後の記録が対象です。以前のCodex budget記録、ネイティブCLIを直接使った呼び出し、
結果が返らなかった呼び出し、ほかのプロジェクトは含みません。完全な課金明細ではありません。
実装検証では有料のモデル生成を実行していないため、更新直後のこのプロジェクトの記録は0件です。

`.verantyx/model-adapters/**/.transport/usage.sqlite3` には数値・モデル名・用途・時刻・リクエストのハッシュを保存します。
キャッシュ継続用のローカル状態はハッシュとネイティブセッションIDを保存します。
なお、会話継続のため、ネイティブCLI自身の通常のセッション保存領域には会話が保存されます。

## 入力欄と状態表示

以前の常設「システム / 操作通知」枠を外し、入力欄の中に状態をまとめました。

- 入力待ち：静止表示。入力欄は1行から、入力内容に合わせて伸びる。
- AIの回答待ち：小さなアニメーションと経過時間。
- ファイル読込・検査・接続ツール実行：処理名と対象を表示。
- あなたの返答待ち：黄色の静止表示。保存された質問がある場合も `idle` にしない。
- 回答の検査・保存：処理中であることを表示。

入力中の背景色は点滅しません。操作ログは `/details` で開けます。
画面が狭い場合は説明行を減らし、会話と入力欄の場所を確保します。
選択中のスクロール、コピー操作は維持しています。F7の端末文字選択中は状態表示も固定します。

アニメーションを止めたい場合:

```sh
VERANTYX_REDUCE_MOTION=1 verantyx --project /Users/motonisihikoudai/Downloads/simureal/cleanroom
```

## 検証と限界

テストでは、JSON分割の復元一致、2回目以降の差分と正しいセッションID、文脈変更時のリセット、
キャッシュ指定のAPI互換性、未報告の利用量の扱い、状態表示を確認しました。
ネイティブCLIとのプロトコル検証は偽のローカル実行ファイル・応答を使い、モデルを呼び出していません。
TUIは実際のレンダラーで140×40、120×28、80×24、60×18を確認しました。
最終の関連テストは172件すべて成功しました。全体1061件の実行で検出した旧ペイロード形式を前提とする
テスト2件も、分割された本文を復元して検証する形に更新し、この再検証に含めています。
全体実行では環境条件によるskipが10件あります。

合成データでは差分が初回入力の1/20未満になるケースを検証していますが、実タスクの節約率ではありません。
キャッシュには最低長・保存期間・モデル・プロバイダー側の条件があります。初回の書き込み費用もあり、
会話を継続しただけで料金が一定割合下がるとは限りません。サブスクリプションの利用枠とAPIの従量料金も別です。
本家と同等の効率かは、同じモデル・依頼・ツール・出力条件で利用量を測って判断する必要があります。
