# CLI優先の実装契約

この実装の目的は二つです。

1. 外部AIに任せた作業から、人間の判断・検証方法・失敗事例を、出典付きの再利用可能な資産へ残す。
2. 自分が学ぶものと、判断を委ねたいものを分ける。本人の理解とシステムの検査結果は混同しない。

モデルは交換可能な提案器です。Kernelが範囲・状態・許可を管理し、固定検査と明示された実行器が観測結果を残します。
提案、許可、実行、検証、採用は別操作です。役割を増やすこと自体を製品の価値とはしません。

## 最小の操作

```sh
verantyx recap RUN_ID
verantyx recap RUN_ID --json
verantyx dictionary --view learn
verantyx dictionary --view delegate
verantyx dictionary --view learn "検索する語"
```

対話中は `/recap` が直前の作業を表示します。`/recap RUN_ID` で保存済みの作業も参照できます。
`/dictionary --view learn` と `/dictionary --view delegate` はAIを呼びません。
通常の `dictionary` と `--view all` は従来の一覧を維持します。

## 三つの結果を混ぜない

`recap` はBUILD、EVIDENCE、OWNERSHIP、実装・統合の記録、実行可能な検査、失敗、未検証のモデル案、人間の選択を区別します。
表示は記録時点の投影です。現在のファイルや許可が有効であるという再認定ではありません。
表示の `ok=true` は記録を読めたという意味で、作業や検査が成功したという意味ではありません。
参照はタスク台帳を更新せずモデルを呼びません。CLIの既存の排他制御は空のロックファイルを作る場合があります。

## 学習と委任

`OWN` は自分で身につけたいもの、`REVIEW` は自分の確認を残すもの、`REFERENCE` は必要時に参照するものです。
この三つと未選択の候補は `learn` に表示します。本人が明示的に選んだ `DELEGATE` は `delegate` に表示します。
保存された規則・検査等は `SYSTEM_REFERENCE` と表示し、人間が選んだ委任とは区別します。

選択は既存の操作で記録します。

```sh
verantyx learn-target RUN_ID --candidate CANDIDATE_ID --target OWN --reason "学びたい理由" --key UNIQUE_KEY
verantyx learn-target RUN_ID --candidate CANDIDATE_ID --target DELEGATE --reason "委ねたい理由" --key OTHER_UNIQUE_KEY
```

学習は任意です。学習しないことだけで安全な作業を止めません。
DELEGATEは無期限の実行許可でも、本人の習熟の証明でもありません。
再質問を省略できるかは、既存の先例・規則の有効性、適用範囲、例外と現在の前提で判定します。

## 実行可能な資産の再利用

保存済みの有限検査は、新しい対象と主張を明示して再利用できます。

```sh
verantyx asset-loop NEW_RUN_ID --asset ASSET_ID --claim CLAIM_ID --target selected.json --key UNIQUE_REUSE_KEY
```

対象は新しい作業の観測・読取範囲に含まれている必要があります。
この明示経路はモデルを呼びません。過去の成功や候補の文章だけでは、新しい依頼との一致や実行許可を認めません。
自由文の一般的な正しさを証明する仕組みではなく、固定した有限条件の検査です。
モデルの提案、引用、実行失敗、検査の反証、結果不明を別々に保持します。

## 立体十字構造体とモデル

`adapters/cross_response.py` は六面にカーネルの状態を配置し、辺で制約を結合して応答方針を計算します。
`adapters/cross_context.py` は原文、版、解釈、実装側の理解、具体例、優先・依存・例外を構造体へ配置して有限の不一致を調べます。
実VMを使った結果は `CROSS_VM`、代替のPython経路は `HOST_FALLBACK` と区別します。
モデルの重みをこの構造体へ圧縮したり、暗号化を保証したり、一般的な意味の正しさを証明する実装ではありません。

## 使用量を抑える境界

辞書、再生、作業要約、明示した検査資産の再利用、固定テストはモデル呼び出し不要です。
実装役と確認役には同じ `gpt-5.3-codex-spark` の `low` を指定します。同じモデルの二つの役割は、独立したモデルによる証明ではありません。
AI呼び出し上限は両役で共有し、役ごとに上限を増殖させません。結果不明時の自動再試行や別モデルへの自動切替も行いません。
回数上限は厳密なトークン料金上限ではありません。実測した使用量と、呼び出さずに済んだ再利用を分けて記録します。

## この段階で完成と呼ばないもの

任意の外部AI利用の自動捕捉、任意タスクの無人実装・採用、自由文の意味の証明、本人の習熟認定、長期運用の使用量削減率は未実証です。
CLIの人工テストと実モデルテストを分けて記録します。Web版の拡張は後段です。
