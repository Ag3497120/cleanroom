# Web検索・本文取得とCLIの読み取り操作

## 最初の設定

プロジェクトを設定済みのディレクトリで実行します。

```sh
verantyx toolbox setup-web --yes
```

MacでJavaScriptを描画してから本文を読む機能も使う場合:

```sh
verantyx toolbox setup-web --browser --yes
```

ブラウザ補助プログラムのビルドにはXcode Command Line Toolsが必要です。
ソースは同梱され、補助プログラムはプロジェクトの `.verantyx/web-tools/` に保存されます。
既存のMCP接続・検査設定・書き込み設定は保持します。同名の別サーバーは上書きしません。

```sh
verantyx web-search "Python 公式ドキュメント"
verantyx web-fetch https://docs.python.org/3/
verantyx web-fetch https://example.com --browser
verantyx toolbox list --server web --yes
```

別の階層から使う場合は `--project /absolute/path/to/project` を付けられます。
TUIでは `/tools` またはF2の「Web & MCP」で設定し、`/web 検索語`、`/browse URL`、
`/browse --browser URL` を入力します。ヘッダーに接続状態が表示されます。
検索・本文取得そのものは言語モデルを呼び出しません。
AIが検索結果を使って回答する場合は、そのAI呼び出しの料金・利用枠が別途発生します。
CLIの検索・取得に失敗した場合はJSONの `ok: false` と終了コード1を返します。

## 実装と範囲

- Verantyxのコミット `bdcd218177430a492375ecdc1675598cda623801` のDuckDuckGo HTML検索方式と、検索一覧・本文取得の分離を移植しました。
- `web_search` はタイトル・URL・要約、`web_fetch` は本文・リンク・取得日時を返します。APIキーは不要です。
- 検索結果が1件でも返せます。検索サイトの拒否・レート制限・HTML変更を「検索結果0件」と混同しません。
- HTTP取得では接続先IPを検証・固定し、リダイレクトも再検査します。ローカルファイルやプライベートIPは取得しません。
- Macの `browser_read` は独立したWebKitプロセスで描画します。サイト本文の抽出が完了してから返します。
- ブラウザは使い捨てのデータ領域を使用し、通常ブラウザのログイン状態を引き継ぎません。画面の前面化、マウス移動、キー入力は行いません。
- WebKitは読み取り専用のデスクトップ操作を保証するOSサンドボックスではありません。ページのJavaScriptとサブリソースは動作します。HTTP取得のIP固定と同等のネットワーク隔離は主張しません。
- CAPTCHAを自動突破する機能や、Bot検知を必ず回避する保証はありません。
- stdio MCPとして公開し、既存の許可リスト・入力検証・呼び出し記録を経由します。検索結果やページ本文を承認・指示として扱いません。

## 選択・コピー

- ドラッグ中にホイール操作すると、始点を保ったまま選択範囲を広げられます。
- 欄の上端・下端へドラッグして保持すると、自動スクロールします。隣の欄や枠の上でマウスを離しても終了します。
- PgUp/PgDnでも選択を保持して移動できます。
- Macではマウス選択を離した時点でシステムのクリップボードへコピーします。選択のハイライトは残り、引き続き範囲を広げられます。
- Command+Cは通常、端末アプリ自身が処理し、CLIへ届きません。このため上記の選択時コピーで受け渡します。Ctrl+C・F6・`/copy` でも明示的にコピーできます。
- コピー時の余分な末尾1文字と、画面上の折り返しによる不要な改行を除きました。
- 選択中の文章は新しい出力で置き換えません。ウィンドウサイズが変わっても、元の文章上の選択位置を保持します。
- Escで選択を解除し、Ctrl+Endまたは `/latest` で最新へ戻れます。F7の端末標準選択も使用できます。

横に十分な幅がある画面では、会話欄約70%、Owner欄約30%に配分します。
F5で現在の欄を全幅表示できます。フッターには閲覧行とコピー・新着の状態を表示します。
