# ChatGPTのSpark接続と省使用量モード

実装役と確認役をともに `gpt-5.3-codex-spark`、推論設定 `low` に固定したCLI接続です。
既にログイン済みのCodex CLIのChatGPT認証を使います。APIキー課金への自動切替はしません。

## 一度の設定

設定済みの対象プロジェクトで実行します。`codex-config` の作成先は新しいディレクトリを指定してください。
現在のMacでは `/opt/homebrew/bin/codex` を使います。認証情報をVerantyxの設定ファイルへコピーする必要はありません。

```sh
verantyx codex-config --directory .spark-session --max-calls 2
verantyx ask "依頼文" --adapter .spark-session/verification.json --editor-adapter .spark-session/implementation.json --include 対象ファイル --include 固定テスト.py --economy --key 一意な作業キー
verantyx codex-usage --directory .spark-session
```

対話で使う場合も同じ設定を指定できます。

```sh
verantyx start --adapter .spark-session/verification.json --editor-adapter .spark-session/implementation.json --economy
```

`--max-calls 2` は**この設定セッション全体で両役合計2回**という上限です。役ごとに2回ではありません。
新しい依頼を続ける分の枠が必要なら、最初の設定時にその分の上限を明示します。
既存セッションを自動で初期化したり、枠切れ時に裏で新しいセッションへ切り替えたりはしません。

## 通常の4回を2回にする

通常の二役経路には、最初の提案、条件の解釈、実装案、最後の説明という4つの生成段階があります。
省使用量モードは最初の観測提案を決定的なローカル処理、最後の説明をカーネルの状態表示に置き換えます。

```text
原文・選択ファイル
  -> ローカルの観測提案
  -> Spark low: 条件の解釈
  -> Spark low: 実装案
  -> Cross: 有限の引継ぎ照合
  -> ローカルの状態説明・経験辞書
```

AIによる自動差戻しとAIによる追加検査生成は、このモードでは増殖させません。
不一致なら記録して停止します。固定テストや既存の `asset-loop --asset` は、許可・範囲を確認したうえでモデルなしに実行できます。
最終説明の `FALLBACK` は、このモードでは意図したローカル説明を意味します。`generator_error=null` と併せて確認できます。
通常モードのモデル障害による代替説明と混同しないよう、応答には `model_call_policy` を含めています。

## 再利用と会計

同じ作業キー・同じ依頼の再実行は既存のワークフロー台帳を使います。
モデル接続にも、要求全体・役割・モデル・設定が完全一致した成功応答のキャッシュがあります。
キャッシュを返す前に現在のローカル検証器を通し、入力が変われば別扱いにします。
未完了や結果不明の予約を、自動で再実行しません。

`codex-usage` は予約済み回数、残り回数、役割別回数、プロバイダーから得られたトークン数と、トークン数が取得できなかった呼び出しを分けて返します。
失敗や中断にも枠を消費する保守的な方式です。API側の処理結果が不明なときに、料金や使用量がゼロだったとは推測しません。
呼び出し数の上限はトークン数・料金の厳密な上限ではありません。4回から2回への削減は呼び出し回数の比較で、トークン使用量半減の保証ではありません。

## 権限と独立性

実装役も確認役も同じモデルです。別々の役割であっても、独立モデルによる証明や本人の判断にはなりません。
モデルは読み取り専用の空の作業ディレクトリから呼び出し、ユーザーの追加設定、シェル、Web検索、サブエージェントの起動を外します。
渡すのは明示したVerantyxの要求JSONです。出力の実行・採用は従来のカーネルのゲートを通します。
この接続はローカルの信頼された開発用途です。認証済みの実行器を公開サイトから無制限に呼ばせる構成にはしません。

公式資料: [非対話CLI](https://learn.chatgpt.com/docs/non-interactive-mode)、[認証](https://learn.chatgpt.com/docs/auth)、[モデル](https://learn.chatgpt.com/docs/models)。

## CLI 内部の再試行と上限の境界

共有予算は Verantyx が起動する `codex exec` の予約回数です。Verantyx 自身は失敗した予約を自動再試行しませんが、Codex 内部の通信再試行を個別に計数・禁止する保証はありません。組み込みの `openai` 接続先は上書き禁止のため、再試行設定を変更する目的でも再定義しません。予約上限はトークン数・課金額・内部 HTTP リクエスト数の厳密な上限ではありません。

## Spark 実接続で判明した出力形式の境界

検証計画と実装案は、`document` を文字列化した JSON として二重に包まず、閉じた構造化 JSON オブジェクトとして受け取ります。実装案の `files` だけを `{path, content}` の配列で転送し、重複パスを拒否してから元の辞書へ戻します。原文、解釈、反例、選択内容、コードの空白を意味的に補正する処理はありません。既存のローカル契約検証、固定テスト保護、Cross での受け渡し比較はそのまま実行します。

実接続で失敗した呼び出しも予約・使用量記録に残します。開発者が原因を修正した後の別の実験は、過去の失敗を消す自動再試行ではありません。
